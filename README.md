# 基于边缘 AI 的电机智能状态监控

**Edge-AI Motor Condition Monitoring** · 本科毕业设计项目

基于 STM32F407ZGT6 + NanoEdge AI 的电机异常状态在线监测系统。单片机端实时计算唯一特征量
**R = 转速 / 母线电压**，用 NanoEdge AI（ZSM 库）在板上做异常检测，OLED 本地报警；
同时经 UART 把 42 字节遥测帧发给 ESP8266（D1 mini），在手机或电脑浏览器上实时查看
转速、电压、电流与 AI 状态。

> 全套新增器件 **¥244.50**（在用 ¥194.98 / 备件 ¥49.52，主控开发板由实验室提供不计），全程零焊接。

| 关键指标 | 数值 |
|---|---|
| 特征量 | R = rpm / V_bus（单变量，避免多维特征冗余） |
| 特征窗 | 32 点 × 100 ms = **3.2 s** |
| 模型 | NanoEdge AI **ZSM**，result_id 44，RAM 56 B / Flash 40 B |
| 学习基线 | **64 窗**（约 6.4 s），库端 `learning_min_iteration = 16` |
| 报警判定 | 相似度 < **32** 连续 2 窗 |
| 检测时延 | 捏轴后约 **3~3.5 s** 报警，松开后自动解除 |
| 固件尺寸 | Code 18200 / RO 3480 / RW 216 / ZI 14216 B |

### 为什么选 R = rpm / 母线电压 作为唯一特征量

老师意见是「19 个特征值太多，要单一变量下的异常检测」。逐个实测对比后排除的方案：

| 候选特征 | 结论 |
|---|---|
| 裸转速 | 负载变化 −17% 与低电量 −11% 的区间重叠，无法区分 |
| 电流波形 | 20 kHz PWM 在板上采不全，与异常的相关系数仅 0.0106 |
| **R = rpm / V_bus** | 正常区间 **13.23~13.53**，捏轴异常 **10.79~11.07**，两段分离干净 |

R 的物理含义是「单位母线电压能换来多少转速」，即电机的机电转换效率。负载变重或电池变弱
都会压低转速，但只有负载变重会同时压低 R —— 这就是它能单变量区分二者的原因。
完整推导见 [`docs/设计方案_最终版.md`](docs/设计方案_最终版.md) 第 4 章。

## 编译产物尺寸

Keil 最终构建，完整日志见 [`firmware_stm32/USER/build_r64.log`](firmware_stm32/USER/build_r64.log)：

| 段 | 大小 |
|---|---|
| Code | 18200 B |
| RO-data | 3480 B |
| RW-data | 216 B |
| ZI-data | 14216 B |
| 合计 ROM | 21896 B（Code + RO + RW） |

共 27 个编译单元（26 个 `.c` + 1 个启动文件），FWLIB 只保留 misc / adc / dma / gpio / rcc / tim / usart。
`OBJ_firmware/` 里的 `.hex` 与 `.map` 是同一次构建产物，`.map` 的 Grand Totals 与上表一致。

NanoEdge AI 模型本身只占 **RAM 56 B / Flash 40 B**。库端 `learning_min_iteration = 16`
是模型的最小迭代次数，固件实际用 `AI_MONITOR_LEARN_WINDOWS = 64` 窗来保证基线稳定
（16 窗在冷机起转阶段容易学到偏高的转速），两者不是同一个参数。

## 实测效果

- 开机起转后 **6~9 s** 学满 64 窗基线，进入检测模式
- 捏轴堵转：相似度 100 → 68 → 16 → **0**，约 **3~3.5 s** 触发报警（PF9 低电平点亮）
- 松开恢复正常后自动解除报警，无需复位
- 稳态复核：110 s 内 phase=2 / 相似度=100 / 零误报；长跑 32 min 约 1.9 万次判定零误报
- 离线验证：正常 2029 窗 0% 误报、异常 1113 窗 100% 检出、低电量 182 窗 0% 误报

四种页面状态的实测截图见 [`docs/`](docs/)：`页面实拍_正常检测.jpg`、`页面实拍_异常报警.jpg`、
`页面实拍_学习中.jpg`、`页面实拍_学习中停机.jpg`。

### 使用边界（会踩到的两个坑）

1. **模型容差约 ±2% R**。机械负载自跳会让转速在 150~216 rpm 之间漂移，因此**电机必须固定**
   （夹具或双面胶压住），否则相似度会自然下滑。
2. **冷机与热机的基线不同**。转速侧存在冷热漂移（热机转速高约 2%），基线必须在冷机时学；
   固件用「停机 0.5 s 后起转自动重学」兜底，所以换工况时先停一下再转即可。

## 复现步骤

### 1. STM32 固件

1. Keil MDK 5 打开 `firmware_stm32/USER/STM32F407_Template.uvprojx`
2. Build（或直接用 `firmware_stm32/OBJ_firmware/STM32F407_Template.hex` 烧录）
3. 首次上电保持电机停转 → 自动完成电流零点校准（64 次平均）
4. 按 PE3 / PE2 切档起步，转起来后等 OLED 上 `S:` 达到 100

### 2. D1 mini 网页监视器

1. Arduino IDE 装 ESP8266 支持，打开 `firmware_d1mini/d1mini_telemetry.ino`
2. 把 `wifi_config.h` 里的 `D1_WIFI_SSID` / `D1_WIFI_PASSWORD` 改成你的热点（仓库里是占位符）
3. 烧录后打开串口（**115200**），等它打印 `STA_READY ip=...`
4. 手机或电脑连同一个热点，浏览器访问 `http://<那个 IP>`

**关于访问地址**：本机实测为 **http://192.168.157.79**，但这是 DHCP 分配的，换了环境就会变。
随时往串口发一个字符 `p`，固件会打印当前 STA 地址 / AP 地址与访问 URL（`?` 打印自检信息）。
如果 20 s 内连不上热点，D1 会自动转为 **AP 兜底模式**，自开热点并把页面挂在固定地址
**http://192.168.4.1**，此时热点名与随机密码同样用 `p` 打印。

### 3. 训练自己的 NanoEdge AI 模型（可选）

数据集在 `dataset/`，每行 32 个数（一个 3.2 s 特征窗的 R 序列），无表头无标签。
在 NanoEdge AI Studio 新建工程：信号长度 32 点、**1 维**，**务必手动关闭 Detrend**
（开着会把 R 的均值差异一起抹平，模型直接失效），然后按正常 / 异常分别导入 CSV。
推荐算法 ZSM，参数见 `docs/zsm_model_params.json`。
