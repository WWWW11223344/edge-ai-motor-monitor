## 3 冷机 → 热机的基线漂移（重要发现）

连续跑 5 分钟后，工况稳定但相似度落在 **67 ~ 75**，不再回到 100：

| 阶段 | rpm | 母线 | R | 相似度 |
|---|---|---|---|---|
| 冷机（刚学完） | 139.6 ~ 140.8 | 10.85 V | 12.87 ~ 12.96 | 100 |
| 热机（跑 5 分钟后） | 142.5 ~ 143.1 | 10.85 V | 13.05 ~ 13.24 | 67 ~ 75 |

**原因**：电机跑热后摩擦变小，同占空比下转速从 139.6 升到 142.5（+2%），
R 随之升高约 2%。而基线是在冷机上学到的，所以热机后偏离了约 2 个标准差。
母线电压没变（10.85 V 稳定），**漂移来自转速侧，不是电量侧**。

**这不是漂移失控**：50 秒连续采样显示相似度在 67~75 之间来回摆，没有继续下滑。

**已有的应对**：`AI_MONITOR_RELEARN_DETECTS = 6000`（约 10 分钟）会触发周期重学习，
把基线重新对齐到当前热机工况，相似度会回到 100。重学习的门槛是相似度 ≥ 20
（`RELEARN_MIN_SIM`），低于它才拒绝重学——早期版本用「未报警」当门槛，已被证明
会与工况漂移互相锁死，§7.3 有完整记录。

**当前余量**（按当时的阈值 48 计算）：热机状态相似度 67~75，余量 19~27 分；捏轴时 0~16，余量 32 分以上。
两侧都比较宽，**按离线数据看阈值 48 不需要改**；但 20:45 上板复测（§6.2）发现 48 会误报，最终值取 32。

**答辩可讲的话**：固定 R 阈值（12.0）也能分开这两类，但 AI 除了给「是/否」，
还给一个连续的相似度，并且靠周期重学习自动跟随电机温升，不需要人工重标定阈值——
这是用模型而不是用单点阈值的主要理由。

## 7 追查「不捏也报警」：不是模型坏，是工况变了 + 重学习死锁（21:00）

阈值降到 32 之后，宝子仍然反馈：**手完全不碰电机，屏上相似度也会掉到 20 多并报警。**
这一节是完整的根因链条。

### 7.1 现象：转速很稳，相似度却在乱跳

正常运转连采 60 点（每 0.5 s 一点）：

| 量 | 波动 |
|---|---|
| 转速 | 147~149 rpm，抖动 **0.43%** |
| R | 13.50~13.80，抖动 **0.47%** |
| 母线 | 稳定 10.83 V |
| **相似度** | **0~100 之间乱跳，均值只有 26** |

转速和 R 都稳到 0.5% 以内，相似度却能跨满量程 —— 这本身就是重要线索：
模型学到的 σ 极小，正常抖动就已经是 1 个 σ，z 值一直贴着判定边界穿。

### 7.2 逐层排除

| 怀疑对象 | 验证方法 | 结论 |
|---|---|---|
| 母线电压掉低（分母变小 → R 虚高） | 由 `V = rpm / R` 反算，V 全程 10.69~11.13 V 稳定 | **排除** |
| 编码器丢脉冲 / 噪声 | 停机后 TIM4 CNT 在 1.2 s 内完全不动 | **排除** |
| 转速窗口被拉长（分母变大 → rpm 虚低） | `encoder.c` 采样在 TIM7 的 1 ms 中断里、按 `s_ms % 100` 触发；实测 s_ms 与墙钟同步（1515/1515 ms、2502/2500 ms） | **排除** |
| **机械负载变化** | 同一 58% 占空比下，两次采集分别**稳定在 150 rpm 和 216 rpm**，R 随之 13.9 ↔ 20~23.5 | **真因** |

关键判据：**rpm 216 是真的**。编码器干净、电压干净、段内极稳，说明负载掉了约 30%，
R 跟着变 47%（`R = rpm / V`），模型判异常**在逻辑上是对的**——这不是误报。

同时抓 `s_win`（140 次，每次 32 个 R 值）还看到窗口里**连续一段 R 飙到 17.2~17.5**，
与 216 rpm 那一段完全对应。

### 7.3 真因二：固件把重学习彻底锁死

`ai_monitor.c` 里周期重学习的累计条件原来是 `if (g_alarm == 0U)`。
设计本意是「报警时别把异常学成正常」，但实际后果是死锁：

```
工况整体漂移 → 相似度长期偏低 → 报警不解除 → 重学习永不触发 → 基线永不更新 → 再也回不来
```

实测证据：`g_detectCount` 冻结在 2428、`g_learned` 一直是 64，跑多久都不重学。

### 7.4 两处修改

**（1）重学习门槛：从「没报警」改为「非硬故障」**

```c
/* 原来：报警就完全不累计，会死锁 */
if (g_alarm == 0U)

/* 现在：只有落在硬故障区间才拒绝重学 */
if (g_similarity >= AI_MONITOR_RELEARN_MIN_SIM)   /* 20 */
```

`RELEARN_MIN_SIM` 取 20 的依据：捏轴实测相似度**全程 0**（只在过渡点出现过 16），
正常侧最低 44。20 正好卡在两者之间——挡得住真故障，又不挡工况漂移。

**（2）停机自动重学基线**

新增 `ai_monitor_notify_stopped()`，由 `main.c` 的 10 ms 块在 `d.speed_rpm < 20.0f` 时调用，
连续 `AI_MONITOR_STOP_TICKS`（50 拍 = 0.5 s）就 `g_learned = 0`、`g_phase = LEARNING`。
换负载、换工况、换电池后**不用断电**，停一下再起转就按新工况重新学 64 窗。

### 7.5 踩坑：第一次写成了死代码

第一版把停机判断写进 `ai_monitor_tick()` 的「窗未满」分支，实测**完全无效**
（停机 1.5 s 后 `g_learned` 仍是 64）。

原因：`main.c` 只在 `feature_r_tick()` 返回 1 时才调 `ai_monitor_tick()`，
而 `feature_r_tick()` 在 `rpm < 20` 时直接 `return 0U` —— **停机时那个函数根本不会被调用**。

**教训：判断「停机」不能写在只有运行中才被调用的函数里，必须由主循环主动通知。**

### 7.10 遗留的物理问题

模型对 R 的容差只有约 ±2%（σ 被压得极小），而**机械负载会自己在 150↔216 rpm 之间跳**。
软件侧现在有「停机再起转自动重学」兜底，但根本解法是**把电机/轮子固定住，别让负载变**。
答辩时这一点可以直接讲成「工况漂移下的在线自适应」——反而是个加分项。

### 10.2 「电流显示为负」的定位与修复（本轮最重要的排查）

**现象**：空载时电流显示为负值（约 −100 mA 量级），停机时却接近 0。

**第一版判断是错的**：我以为是 ACS712 接反，加了 `CURRENT_SIGN = -1.0` 把符号翻过来。否掉它的判据很直接——ACS712 是有符号双向传感器、零点在 `VCC/2`，**真接反的话停机时也会偏**，而实测是「停机准、带载才偏」。该改动已整体回退。

**真因是采样相位混叠**。三个数都是整数倍关系：

```
PWM 周期    20 kHz  = 50 us
采样周期    10 ms   = 200 个 PWM 周期
时基分辨率  1 ms    = 20  个 PWM 周期
```

也就是说，**每次 ADC 采样都落在 PWM 波形的同一个相位上**，8 点滑动平均等于没平均，纹波的直流偏置把读数整体顶歪——停机时 PWM 不输出（没有纹波），所以只有带载才偏。

**修法是给采样点加相位抖动**，用 DWT 周期计数器实现：

```c
#define CURRENT_DITHER_PHASES       8U      /* 一个 PWM 周期铺 8 个相位 */
#define CURRENT_DITHER_STEP_CYCLES  1050U   /* 168 MHz 下 6.25 us，8 x 1050 = 50 us */

/* Current_UpdateFiltered() 里，在 raw = Current_ReadRaw() 之前 */
Current_WaitCycles((uint32_t)g_i_dither * CURRENT_DITHER_STEP_CYCLES);
g_i_dither = (uint8_t)((g_i_dither + 1U) % CURRENT_DITHER_PHASES);
```

**不能用 `Delay_us()` 代替**：软件循环的抖动量本身就接近要测的相位差，等于用一个误差去修另一个误差。

**修复后四个工况的读数全部为正**（见 10.1 表）。最硬的旁证：捏轴时读到 **+196 mA**，与同一天 D1 采集通道独立记录的 `grip` 数据 **+196 mA** 完全吻合——两条互不相干的链路对上了同一个数。

> 附带发现：之前那版加 `CURRENT_SIGN` 的固件其实已经跑死在 HardFault（重烧时 J-Link halt 打印 `IPSR = 003 (HardFault)`）。所以当时看到的「负电流」可能叠加了两个问题——相位混叠，加上死机前冻结的最后一帧。
