# NanoEdge AI Studio 训练操作手册（转速单变量 R）
> **2026-10-21 后续**：现行模型是 **68 号 ICM**（3 维特征 n95 / peak_value / n25 + 35 个聚类中心），不是本文写的 ZSM。**操作步骤全部适用**——新建项目、Signals 导入、关 Detrend、Benchmark、导出库、勾 `-fshort-wchar` 与 `float_abi=hard`，一步步照着做仍然对。
> 需要改的只有三处：① 数据文件换成 `Ripple32_*.csv`（2252 / 3378 行）；② 结果里期待的是 **ICM**，不是 ZSM；③ `input_size` 从 1 变成 **3**（库内把 32 点抽成 3 个特征），固件侧的编译期断言要跟着改。

---

> 目标：在 NanoEdge AI Studio 5.2.0 里新建一个「异常检测」项目，训练出 1 轴 × 32 点的模型，
> 导出 `libneai.a` + `NanoEdgeAI.h`，替换进 STM32 工程。
> 数据已全部备好，不需要你再采一次。

## 0. 一句话总览

| 项 | 值 |
|---|---|
| 项目类型 | **Anomaly Detection**（异常检测，n-class，只用正常数据训练） |
| 目标芯片 | **STMicroelectronics - STM32F4 Series**（Generic） |
| 传感器 / 输入 | **Current**（1 轴，单变量） |
| 采样率 | **10 Hz**（每点 100 ms） |
| Buffer size / 信号长度 | **32**（= 3.2 s） |
| 训练数据 | `R32_regular_normal.csv`（1000 行 × 32 点） |
| 异常数据 | `R32_abnormal_grip.csv`（500 行 × 32 点） |
| 独立测试 | `R32_test_normal_batch06.csv`（569 行 × 32 点，整批没进训练） |

数据目录：

```
H:\毕设设计\output\单变量分析_20261019\nanoedge_r32\
    R32_regular_normal.csv          正常（训练用）
    R32_abnormal_grip.csv           异常（评估检出率用）
    R32_test_normal_batch06.csv     正常（独立测试，验误报）
```

三个文件都已经校验过：**32 列、纯数值、无表头、无 BOM、空格分隔**，符合 Studio 要求。

数据背后的事实（写论文能用）：

| 集合 | R 均值 | R 标准差 | 范围 |
|---|---|---|---|
| 正常（训练） | 13.336 | 0.125 | 13.03 ~ 13.84 |
| 异常（grip） | 10.927 | 0.221 | 10.23 ~ 11.67 |
| 正常（独立测试） | 13.287 | 0.065 | 13.08 ~ 13.52 |

正常与异常均值差 **2.409**，是正常标准差的 **19 倍** —— 可分性极好，模型会很轻松地学到。
**这一点答辩要如实说**：本方案的 AI 本质是「学习 R 的正常分布」，不是「识别波形形状」。

## 1. 第一步：新建项目（DI，Data Import）

1. 点左上角 **`+ NEW PROJECT`**。
2. 弹出项目配置窗口，按下表填：

| 字段 | 填什么 | 说明 |
|---|---|---|
| Project type | **Anomaly Detection** | 不要选 N-class classification |
| Project name | `MotorR_32pts_20261019` | 名字别用中文、别用空格 |
| Target / Board | **STMicroelectronics → STM32F4 Series**（Generic） | 和你现有 4 个项目一致 |
| Sensor | **Current** | 下拉里如果没有 Current，选 `Generic` / `1 axis` 单轴 |
| Sensor type | **Time Series**（时序） | 不要选 Feature / 统计特征 |
| Sampling frequency | **10** Hz | 关键：我们每 100 ms 采一个点 |
| Buffer size / Signal length | **32** | 关键：必须和固件 `FEATURE_R_WINDOW` 一致 |
| Number of axes | **1** | |
| Memory 预算 Flash | 8 KB | F407 有 1 MB，这已经非常宽松 |
| Memory 预算 RAM | 8 KB | F407 有 192 KB |

> **为什么是 32 而不是 16**：Studio 要求 buffer size 是 2 的幂，而且 16 个点太短，
> 会让 FFT 类算法无法参与搜索（ST 工程师在社区明确说过 16 值 buffer 会报 "not sufficient
> values for FFT"）。32 点仍是 2 的幂，FFT 可用，3.2 s 的检测延迟对电机监控完全够。

## 2. 第二步：导入信号（DI 里的 Regular / Abnormal / Test）

界面上会有几个标签页，逐个导入：

| 标签页 | 导入文件 | 行数 |
|---|---|---|
| **Regular signals**（正常 / 标称） | `R32_regular_normal.csv` | 1000 |
| **Abnormal signals**（异常） | `R32_abnormal_grip.csv` | 500 |
| **Test**（如果有这一页） | `R32_test_normal_batch06.csv` | 569 |

导入方式：直接把文件**拖进窗口**，或点 `Import files` / `Add signal` 选文件。

导入后 Studio 会显示：
- Number of signals（=行数）：正常应是 **1000**
- Signal length（=列数）：应是 **32**
- Number of axes：**1**

**如果显示的列数不是 32，或者报到行数不对 —— 停下来说，别继续训。**

---

## 3. 第三步：数据准备（DP，Data Preparation）

这一步主要确认三件事，一般不需要改动：

1. **Slice / Segmentation**：选「整行即一个信号」，不要自动切片（我们的行本来就是切好的窗口）。
2. **Normalization（归一化）**：**选 None**。
   - 有 `Min-Max` 也可以接受（全局线性变换，不改变可分性）。
   - **绝对不要选 Z-score / per-signal / 逐信号标准化** —— 那会把每行的绝对水平拉到同一尺度，
     我们的异常信号恰好就是「水平掉下去」，一标准化就全没了，模型直接失效。
3. **预处理 / 滤波**：全部关闭。R 是慢变标量，不需要去噪。

---

## 4. 第四步：搜索 + 基准（Search / Benchmark）

1. 进入 **Search space** 或 **Find the best model** 页。
2. 搜索空间保持默认（让 Studio 遍历它自己的算法库）。
3. 点 **`RUN` / `Search` / `New benchmark`**。
4. **等待**。1000 × 32 的数据量很小，预计几分钟出结果（旧项目 19 维 × 4 也就十几分钟）。

结果页会给出一个**候选模型排行榜**，每行有这些列：

| 列 | 看什么 |
|---|---|
| **Balanced accuracy** / Score | 首要指标，越高越好 |
| **RAM** | 越小越好，但要 < 8 KB |
| **Flash** | 越小越好 |
| **False positive rate** | 误报率，**答辩权重最高** |
| **Detection rate** | 检出率 |

选模型的顺序：**先排除 RAM/Flash 超标的 → 再看误报率 → 最后看均衡分**。
宁可 RAM 小一半、准确率 97%，也别选准确率 99.5% 但吃掉 20 KB RAM 的。

选好后点 **`SELECT`** / 打勾确认这个模型。

---

## 5. 第五步：编译导出（Compile）

1. 进入 **Compile** 页。
2. 按下表填：

| 字段 | 填什么 |
|---|---|
| Board / MCU | **STM32F407ZG**（或 STM32F4 Series） |
| Compiler / Toolchain | **ARMCC** / **Keil MDK**（工程用的是 Keil MDK 5.14 + ARMCC 5） |
| 优化等级 | `-O2`（默认即可） |
| Library name | `neai`（不要改，工程里链接的就是 libneai.a） |

3. 点 **`COMPILE`**，等它生成，然后 **下载 zip**。

zip 里会有两个必需文件：

```
libneai.a          →  放到  H:\STM32_LERN\19_OLED\NEAI\libneai.a（覆盖旧的）
NanoEdgeAI.h       →  放到  H:\STM32_LERN\19_OLED\NEAI\NanoEdgeAI.h（覆盖旧的）
```

**放好之后告诉我**，我会依次做：
1. 读新的 `NanoEdgeAI.h`，确认 `NEAI_INPUT_SIGNAL_LENGTH` 是否等于 32、`NEAI_INPUT_AXIS_NUMBER` 是否等于 1
2. 改 `ai_monitor.c`：输入长度 76 → 32、输入源从「19 维统计量」换成 `feature_r_get()` 的 32 点 R 序列、
   门禁从 `M2_VALID_ALL`(0x3F) 换成「转速 + 电压」的新宏
3. 取消 `main.c` 里 `ai_monitor_init()` 的注释
4. 重新编译（旧库 RAM 1032 B / Flash 488 B，新库预期更小）
5. 按老规矩关 DMA 烧录、独立回读校验
6. 上板跑：按键升 1 档 → 底条 LRN（学习约 5 s）→ DET → 松开/停转回 SIM

---

## 6. 五个必须避开的坑

1. **别开逐信号归一化**（见第三节）。这是唯一会让整个模型白训的设置。
2. **Buffer size 必须 32**，不能改成 64/128 —— 固件里 `FEATURE_R_WINDOW` 是 32，硬编码对齐。
3. **采样率填 10 Hz**，不是 100 Hz 也不是 1 kHz。R 是 100 ms 一个点。
4. **训练只喂正常数据**。`R32_abnormal_grip.csv` 只能放 Abnormal 页做评估，**绝不能放进 Regular**。
5. **别用 `wave_data` 里那两个 200 点的 nanoedge 文件** —— 那是 20 kHz 电流波形的，与本项目完全不同源。

## 7. 训练完怎么判断这一步算成功

对照下面几条，全过就说明模型可用：

- [ ] 项目卡片显示 **1 Axes**、信号长度 **32**
- [ ] Regular 导入 **1000** 行，Abnormal 导入 **500** 行
- [ ] Benchmark 结果里 **RAM < 2 KB、Flash < 2 KB**（旧 19 维库是 1032 B / 488 B，新库应更小）
- [ ] 排行榜里最好那个模型的**误报率接近 0%**
- [ ] Compile 成功，zip 里 `NanoEdgeAI.h` 里能看到 `NEAI_INPUT_SIGNAL_LENGTH 32`

如果 Benchmark 出来的准确率不到 90%，**先别怀疑工具** —— 大概率是导入时行列错了，
或者归一化开了逐信号。回来找我查。

## 8. 附：本次训练用的数据是怎么造出来的

脚本 `export_r32_for_studio.py`，规则与固件 `feature_r.c` 严格一致，不是随手切的：

1. `raw.csv` 每行 10 ms，编码器每 100 ms 才更新一次转速 → **每 10 行取 1 点**
2. 一个窗口 = **32 个连续点** = 3.2 s
3. 整窗 32 点**必须全部有效**：占空比 > 0、转速 ≥ 20 rpm、母线 ≥ 1.0 V
   （对应固件 `FEATURE_R_RPM_MIN` / `FEATURE_R_VBAT_MIN` 和「停转丢窗」逻辑）
4. stride = 1 点（每 100 ms 产生一个新窗口），与固件滑动窗一致
5. `R = 转速(rpm) / 母线电压(V)`

训练集用 `normal_running_01~05`，测试集用 `normal_running_06`（**整批没参与训练**，
所以测出来的误报率是独立验证结果，答辩可以直接用）。
