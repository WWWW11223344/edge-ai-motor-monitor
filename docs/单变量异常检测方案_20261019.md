# 单变量异常检测方案

- 项目：基于边缘 AI 的电机智能状态监控系统
- 日期：2026-10-19
- 起因：老师意见「19 个特征值太多，只要区分正常/异常的关键变量，最好是单一变量下的异常检测」
- 数据：9 批独立采集（6 批正常 + 3 批负载异常，共 3252 个窗口）+ 1 批低电量对照（182 窗）

---

## 一、结论（先看这里）

**推荐单一变量：单位电压转速**

```
R = 转速(rpm) / 母线电压(V)
```

**正常 13.2 ~ 13.6，异常 < 12.0。报警阈值取 12.0（或学习基线的 90%）。**

在这个变量上，6 批正常数据（2139 窗）**零误报**，3 批负载异常数据（1113 窗）**全部检出**，1 批低电量但工作正常的数据（182 窗）**不误报**。

一句话原理：电机是恒压 PWM 驱动，**转速就是负载的直接读数**。负载变大 → 转速变慢，与电压无关的部分被除以电压消掉。

---

## 二、为什么 19 维可以砍到 1 维

### 2.1 19 个变量里有一大半是同一个东西换算法

对 19 维做相关分析，**|r| > 0.9 的冗余变量对有 20 对**，其中典型的：

| 变量对 | 相关系数 | 说明 |
|---|---|---|
| `current_mean_A` ~ `current_rms_A` | +0.995 | 均值与有效值，交流分量极小时必然重合 |
| `accel_x_mean_g` ~ `accel_x_rms_g` | −1.000 | 完全线性，只差一个符号 |
| `accel_x_mean_g` ~ `accel_z_rms_g` | +0.990 | 都是姿态投影 |
| `accel_x_mean_g` ~ `speed_mean_norm` | +0.952 | 都在反映负载 |
| `accel_x_variance_g2` ~ `accel_x_waveform_factor` | +1.000 | 波形因子 = RMS/均值，方差小时退化为线性函数 |

**这说明 19 维的真正独立信息量远小于 19。** 这是对老师意见最直接的数据支撑：不是「砍掉有用特征」，而是「这 19 维本来就在重复表达同一件事」。

### 2.2 单变量区分力排名（6 批正常 vs 3 批异常，按批间不重叠程度）

不只看「两类均值差多少」，而是看**正常批与异常批的均值区间是否真的不重叠**——这才是跨批次能不能用的判据。

| 排名 | 变量 | 正常 6 批均值范围 | 异常 3 批均值范围 | 区间间隙 | 相当于几个批内 sd | 判定 |
|---|---|---|---|---|---|---|
| 1 | `speed_mean_norm`（转速） | 0.2941 ~ 0.3004 | 0.2391 ~ 0.2449 | +0.0492 | **26.9** | 完全分开 |
| 2 | `accel_z_rms_g`（Z 轴振动） | 0.2557 ~ 0.2739 | 0.1459 ~ 0.1877 | +0.0680 | **18.3** | 完全分开 |
| 3 | `accel_x_mean_g` | −0.9221 ~ −0.9160 | −0.9462 ~ −0.9383 | +0.0162 | 9.3 | 分开但见 2.3 警告 |
| 4 | `accel_x_rms_g` | 0.9161 ~ 0.9223 | 0.9383 ~ 0.9463 | +0.0160 | 8.9 | 同上 |
| 5 | `accel_y_mean_g` | −0.0420 ~ −0.0405 | −0.0494 ~ −0.0489 | +0.0069 | 7.1 | 同上 |
| 6 | `speed_std_norm`（转速波动） | 0.00045 ~ 0.00057 | 0.00139 ~ 0.00212 | +0.00082 | 3.3 | 可用 |
| 7 | `current_mean_A`（电流） | 0.0784 ~ 0.0889 | 0.0975 ~ 0.1104 | +0.0086 | **0.93** | 勉强 |
| 8~19 | 其余 12 维 | — | — | ≤ 0.63 | ≤ 0.63 | 单变量不可用 |

### 2.3 为什么不选加速度（哪怕它也是 100%）

`accel_x_mean_g` 能从 −0.921 变到 −0.946，差 0.025 g。**这不是故障特征，这是传感器倾角变了 1.5 度。**

0.025 g / 1 g = 2.5%，对应姿态角约 1.4°。也就是说：**只要安装时手抖一下、垫片厚 0.2 mm、桌面不平，这个「特征」就完全变了**，而电机其实好好的。

同理 `accel_z_rms_g` 从 0.257 掉到 0.166（−36%），主要也是振动传导路径变了（不同批次摆放位置/垫材不同），不是电机状态。

**这类特征在实验室看着很漂亮（100% 分离），一换安装就是灾难。** 答辩时一定会被问「你换个人装还准吗」，答不上来。

### 2.4 为什么不选电流（看着最符合物理，实测最差）

物理上讲得通：负载↑ → 电流↑。实测也确实升了（0.082 → 0.105 A，+27%）。

但**正常批之间的电流差异（0.0784 ~ 0.0889，跨度 13%）几乎和正常→异常的差（+27% 的一半）一个量级**，区间间隙只有 0.93 个批内标准差。

原因：电流对**摩擦、装配、温漂、电源纹波**都敏感，而转速对这些不敏感（转速由电压和负载决定，摩擦已经包含在负载里但被减速比和反电动势压住了）。

**结论：电流适合做「辅助判据」，不适合做唯一判据。**

## 三、关键发现：不做电压归一化，会大面积误报

这是本方案最重要的一条，也是答辩时最能体现「你想过」的地方。

手头有一批 `controlled_vibration_20261008_tabletop02_test` 数据（182 窗），母线只有 **9.85 V**（正常批是 11.1 V），但电机本身工作正常。

用**裸转速**判断：

| 指标 | 正常 6 批 | 该批（低电量，正常） |
|---|---|---|
| 转速均值 | 147.2 rpm | 121.8 rpm |
| 与正常批差异 | — | **−17.2%** |
| 若阈值设在 130 rpm | 0% 误报 | **100% 误报** |

**电压掉了 11%，转速跟着掉 17%，看起来和「负载异常」一模一样。**

### 归一化后

| 数据 | 母线电压 | 转速 | `rpm/V` | 判定 |
|---|---|---|---|---|
| 正常 6 批 | 11.09 V | 147.2 rpm | **13.23 ~ 13.53** | 正常 ✓ |
| 低电量批（工作正常） | 9.85 V | 121.8 rpm | **12.37** | 正常 ✓ |
| 负载异常 3 批 | 11.07 V | 121.0 rpm | **10.79 ~ 11.07** | 异常 ✓ |

三者被干净地分成三段。**除以电压这一步，把「电池没电」和「电机带载异常」彻底分开了。**

> 顺带一个诚实的说明：当年那批「轻敲能分开」的结论，很可能是被这 11% 的电压差带出来的，不完全是敲击本身的贡献。论文里如果要引用那批数据，必须注明电压条件不同。

## 四、阈值怎么定

### 4.1 阈值扫描结果

| 阈值 T（`rpm/V` < T 判异常） | 正常 6 批误报率 | 异常 3 批检出率 | 低电量批误报率 |
|---|---|---|---|
| 12.6 | 0.00% | 100.00% | **100.0%** |
| 12.4 | 0.00% | 100.00% | 89.6% |
| **12.2** | 0.00% | 100.00% | 0.0% |
| **12.0** | **0.00%** | **100.00%** | **0.0%** |
| 11.8 | 0.00% | 100.00% | 0.0% |
| 11.6 | 0.00% | 100.00% | 0.0% |
| 11.4 | 0.00% | 97.84% | 0.0% |
| 11.2 | 0.00% | 90.57% | 0.0% |
| 11.0 | 0.00% | 67.30% | 0.0% |

**可用区间：11.6 ~ 12.2。取中点 12.0。**

### 4.2 推荐写法：相对基线

绝对值 12.0 是这一台电机、这一套机械结构的数。换电机/换齿轮箱要重标定。更稳的做法是**上电学习基线**：

```
学习阶段（约 20 秒，电机空载或带标准负载运转）
    R0 = 窗口 rpm/V 的均值
报警阈值
    ALARM_TH = 0.90 × R0        // 允许下降 10%
```

实测 R0 ≈ 13.3 → 阈值 11.97，与绝对阈值 12.0 一致，但具备了自适应性。

**裕量核算**（阈值 12.0 时）：
- 距离正常批单窗最低值 13.09：**+8.3%**
- 距离异常批单窗最高值 11.55：**−3.9%**
- 距离低电量批 12.37：**+3.1%**

三边都有余量，不是贴着边界切的。

## 五、固件怎么改

### 5.1 改动清单

| 文件 | 现在 | 改成 |
|---|---|---|
| `feature19.h` | `FEATURE19_COUNT 19` | `FEATURE19_COUNT 1`（保留文件名，避免动工程配置） |
| `feature19.c` | 算 19 个统计量 | 只算窗口内 `rpm/电压` 的均值 |
| `ai_monitor.h` | `AI_MONITOR_SAMPLES 4`（4×19=76） | 保持 4（4×1=4） |
| `ai_monitor.c` | 填 76 个 float | 填 4 个 float |
| NanoEdge 库 | 19 轴 × 4 样本 | **1 轴 × 4 样本，需在 Studio 重新生成** |
| `ui.c` | 显示 `Spd` / `I` | 增加一行显示 `R=13.29`（可解释性） |
| `m2_protocol.c` | 帧里已含 `rpm_x10` 和 `battery_mV` | **不用改**，两个原始量早就传了 |

### 5.2 核心计算（可直接用）

`feature19.c` 里原来的 19 维统计全部可以删掉，只留：

```c
/* 计算一窗的「单位电压转速」rpm/V
 * 输入：窗口内 64 帧（已校验序号连续、间隔 <= 20 ms、档位未变）
 * 输出：均值放到 *out，异常时返回对应状态码
 */
static Feature19Status unit_speed_ratio(const M2Frame *frame,
                                        uint32_t count, float *out)
{
    float    rpm_sum = 0.0f;    /* 转速累加（rpm） */
    float    vol_sum = 0.0f;    /* 母线电压累加（V） */
    uint32_t i = 0U;            /* 循环变量 */

    if ((frame == NULL) || (out == NULL) || (count == 0U))
    {
        return FEATURE19_ARGUMENT;          /* 入参错误 */
    }

    for (i = 0U; i < count; i++)
    {
        /* 转速：帧里是 rpm×10 的 int32（单位 0.1 rpm） */
        rpm_sum += (float)frame[i].speed_rpm_x10 / 10.0f;
        /* 母线电压：帧里是 mV 的 int32 */
        vol_sum += (float)frame[i].battery_mv / 1000.0f;
    }

    /* 除零保护：电压异常低时窗口作废，不做假数据 */
    if (vol_sum < 1.0f)
    {
        return FEATURE19_NUMERIC;
    }

    *out = (rpm_sum / (float)count) / (vol_sum / (float)count);
    return FEATURE19_OK;
}
```

计算量对比：原来一窗要算 5 组统计量（均值/RMS/峰峰值/方差/波形因子）+ 开方 + 除法，现在只要**两次累加 + 一次除法**。168 MHz 下耗时从几百微秒降到几微秒，栈占用也降。

### 5.3 判定逻辑

```c
/* 报警判定：连续 2 窗低于阈值才报警，连续 2 窗恢复才解除
 * 沿用现有 ai_monitor.c 的 ALARM_WINDOWS / CLEAR_WINDOWS 机制，不改架构
 */
if (ratio < g_alarm_threshold)      /* g_alarm_threshold = 0.90f * R0 */
{
    g_below_count++;                /* 连续偏低计数 */
}
else
{
    g_below_count = 0U;             /* 一旦恢复就清零 */
}
```

### 5.4 关于「边缘 AI 还要不要」

两条路，都能过答辩，取舍不同：

| | 路线 A：单变量 + 自适应阈值 | 路线 B：单变量 + NanoEdge 学习 |
|---|---|---|
| 输入 | 1 个 float（窗口均值） | 4 个 float（4 个连续窗口） |
| 是否要重新训练模型 | **不用**，改 C 代码即可 | 要在 Studio 重新生成 1 轴库 |
| 代码量 | 改 2 个文件 | 改 2 个文件 + 换库 |
| 准确率 | 实测 0% 误报 / 100% 检出 | 理论相当（单变量信息量相同） |
| 答辩讲什么 | 「负载→转速」的物理机制 + 数据验证 | 「AI 学到了正常转速分布」 |
| 风险 | 老师可能问「你的 AI 在哪」 | 4 个点学不出稳定分布，可能效果不如阈值 |

**推荐方案已按第八节的参考案例修正：路线 C（20 kHz 电流波形）优于路线 A（阈值），路线 B 不建议。**

原因见 8.3：把 `rpm/V` 做成 1 轴 × 16 点时间窗，形式上和电位器案例一样，但实测窗口内形状自相关 ≈ 0，AI 实际只能学到均值，等价于阈值。而 `fastcap.c` 的 20 kHz 电流波形是真正的未混叠信号，形状里有信息。

## 六、论文/答辩怎么写

### 6.1 建议的论证链条（四步，每步都有数据）

1. **问题**：19 维特征存在严重冗余 —— 20 对变量 |r|>0.9，真正独立信息量远小于 19。
2. **筛选**：用「批间区间不重叠度」而不是「两类均值差」做判据 —— 6 批正常 vs 3 批异常，转速分离度 26.9 个批内标准差，电流只有 0.93。
3. **关键设计**：负载异常会使转速下降，但**电源电压下降也会**。因此引入单位电压转速 `R = rpm/V` 做归一化，把两者分开。实测低电量批 9.85 V 时不误报。
4. **验证**：阈值 12.0 下，6 批正常 2139 窗 0% 误报，3 批异常 1113 窗 100% 检出，1 批低电量对照 0% 误报。

### 6.2 和原来 19 维方案怎么比

| 维度 | 19 维 + NanoEdge | 1 维（rpm/V）+ 阈值 |
|---|---|---|
| 特征数 | 19 | **1** |
| 板上计算量 | 5 组统计量 × 4 段 | **2 次累加 + 1 次除法** |
| 可解释性 | 黑箱相似度 0~100 | **物理量，能直接读出负载状态** |
| 跨批稳定性 | 未知（未做跨批验证） | **已做 9 批交叉验证** |
| 安装敏感性 | 高（含 6 个姿态相关维度） | **低（转速不受安装影响）** |
| 电源电压敏感 | 高（转速/加速度都受影响） | **已归一化消除** |

### 6.3 老师可能追问的三个问题，提前准备

**Q1：只用转速，那振动传感器不是白装了？**
A：不是。转速负责「负载类异常」（堵转、卡滞、轴承磨损），这部分是单变量强项。振动负责「冲击类异常」（敲击、松动），这类事件转速来不及响应。当前版本先把主判据收敛到单变量，振动留作二期扩展——**这是主动的范围收缩，不是遗漏**。

**Q2：只有一台电机、9 批数据，100% 是不是过拟合？**
A：阈值只用了 1 个参数（12.0），且阈值两侧各有 3.9% 和 8.3% 的裕量，可用区间宽达 11.6~12.2。另外做了**留一批验证**：任意剔除 1 批正常数据，剩余 5 批定的阈值仍能正确分类留出批。参数少到不可能过拟合。

**Q3：换个电机还准吗？**
A：绝对值阈值需要重标定，所以方案里给了相对写法：`阈值 = 0.90 × 上电学习到的基线`。换电机只要重新学习 20 秒，不用改代码。

## 七、这个方案的边界（必须写进论文的局限）

1. **只能检测「负载类」异常。** 转速对负载敏感，对「突然的冲击」不敏感（冲击持续时间 < 1 个窗口 1.28 s 时可能漏掉）。
2. **只覆盖 1 档 58% 占空比。** 档位变化时 `rpm/V` 会变，必须先按档位分别学习基线。当前固件只有 0 与 1 两档，L1 停转时不检测，不冲突。
3. **不能定位故障类型。** 单变量只能回答「有没有异常」，不能回答「是轴承还是绕组」。要进一步定位必须回到多变量或频域分析（`fastcap.c` 的 20 kHz 数据是现成的路径，但尚未接入）。
4. **样本量有限。** 3 批异常数据都是「手捏紧」模拟，不是真实的轴承磨损/绕组短路。论文里必须写明「以外部加载模拟负载异常」。
5. **低电量批只有 1 批。** 归一化有效性还需要在更宽电压范围（如 9.0 ~ 12.6 V）再采 2~3 批确认。

## 八、补充：关于「电位器监测」参考案例的分析

参考资料：`H:\毕设设计\资料\边缘AI\ai_Studio_f407_电位器监测\ai_f407\docs\ai_f407_edge_ai_guide.md`
（同目录下 `电压-nanoedgeAI\nanoedgeAI` 是 F103 版本，参数一致）

### 8.1 先分清两个概念：电位器和电压不是一回事

| | 电位器 | 电压 |
|---|---|---|
| 是什么 | **器件**（三端可变电阻，中间抽头输出分压） | **物理量**（单位 V） |
| 在例子里的角色 | 信号源：拧旋钮 → 抽头电压变化 | 被监测的对象 |
| 代码里看到的 | 没人读电位器 | `PA5` 上的 ADC 原始码 `0~4095` |

那个例子的完整链路是：

```
电位器旋钮位置 → PA5 抽头电压 → ADC1 原始码(0~4095) → 19 点 float 窗口 → NanoEdgeAI
```

**所以严格说，它做的是「单路模拟电压信号的异常检测」，电位器只是产生电压的手段。**
`ai_f407_edge_ai_guide.md` 第 680 行也明确写了：传给 AI 的是 `ADC 原始值`，不是电压值。

### 8.2 两个「19」完全不是一回事（关键）

| | 别人例子的 19 | 本项目的 19 |
|---|---|---|
| 19 的含义 | **时间长度**：19 个连续采样点 | **特征维度**：19 个不同统计量 |
| 采样间隔 | 10 ms × 19 = 190 ms 一条波形 | — |
| AI 输入形状 | `1 轴 × 19 点 = 19 个 float` | `19 轴 × 4 样本 = 76 个 float` |
| 变量数 | **1 个**（只有 PA5 电压） | 19 个（电流/加速度/转速/电压…） |
| AI 学的是 | 一条波形的**形状** | 19 个指标的**数值组合** |

老师嫌多的是**右边那种**（19 个维度）。而别人的例子恰好是**左边那种**（1 个变量、19 个时间点）。

**结论：这个案例完全支持老师的意见，而且是「单变量」的教科书做法 —— 变量只留一个，但窗口里放的是一长串连续采样点，不是一堆统计量。**

### 8.3 但直接照搬会踩坑：在 20 ms 采样下，形状里没有可学的信息

别人的信号是 **ADC 逐点原始码（未平滑）**，10 ms 一个点，形状里包含接触不良的尖峰、转动趋势、电源纹波。
本项目遥测是 **20 ms 一帧**，且转速、电流都是已算好的量。

实测「窗口内形状是否有稳定模式」——做法是每个窗口去掉均值后做归一化，再算窗口之间的平均相关系数（形状自相关）。**如果接近 0，说明每窗形状互不相关，就是随机噪声，AI 学不到东西。**

| 信号 | 窗口 | 正常批的形状自相关 | 异常批的形状自相关 |
|---|---|---|---|
| `rpm/V`（100ms/点） | 16 点 = 1.6 s | −0.005 ~ +0.002 | −0.006 ~ −0.005 |
| `accel_z_mg` | 64 点 = 1.28 s | −0.005 ~ +0.008 | −0.002 ~ 0.000 |
| `accel_x_mg` | 64 点 = 1.28 s | −0.004 ~ +0.006 | −0.002 ~ +0.001 |
| `current_mA` | 64 点 = 1.28 s | −0.002 ~ +0.002 | −0.002 ~ +0.004 |

**全部 ≈ 0。** 三个信号在 20 ms 采样下都学不出形状。

原因有两个：
1. **欠采样**：电机振动主频在几十到几百 Hz，20 ms（50 Hz）采样必然混叠，波形退化成随机数。
2. **已被平滑**：`current_mA` 是 8 点滑动平均后的值，`rpm` 是 100 ms 窗口计数，本身就不是原始波形。

**所以：如果把 `rpm/V` 做成 1 轴 × 16 点喂给 NanoEdge，形式上和别人一样，实质上 AI 只能学到「均值高低」，等价于一个阈值 —— 答辩时被追问「AI 到底学到了什么」会很难回答。**

### 8.4 要真正复刻这个案例，得用未被欠采样的原始波形

现成的候选只有一个：**`fastcap.c` 的 20 kHz 电流采样**。

- TIM3 触发 ADC2 + DMA2 循环搬运，**200 点一帧**，10 ms 一帧 → 天然是「1 轴 × 200 点」波形
- 采样率 20 kHz，能覆盖电机换向纹波与 PWM 纹波，**形状里真的有信息**
- 变量只有**一路电流**，完全满足「单一变量」
- 固件里已经实现并在跑，只是目前只出直流/RMS/峰峰值，**没有接入模型**

这条路是把「老师要的单变量」和「毕设要的边缘 AI」同时满足的最优解，代价是要重新采一批训练数据（每批 30 秒即可）。

### 8.5 三条路线对比

| | A 单变量阈值 | B 单变量时间窗（照搬形式） | C 单变量电流波形 |
|---|---|---|---|
| 变量 | `rpm/V` | `rpm/V` | **电流（20 kHz 波形）** |
| AI 输入 | 无用（纯阈值） | 1 轴 × 16 点 | **1 轴 × 200 点** |
| 形状可学 | — | **否**（实测自相关 ≈ 0） | **是**（20 kHz 未混叠） |
| 要重新采数据 | 不用 | 不用 | **要（约 9 批 × 30 秒）** |
| 要进 NanoEdge Studio | 不用 | 要 | 要 |
| 改固件工作量 | 小（2 个文件） | 中 | 中（fastcap 已在跑，只需接窗口） |
| 板载 RAM | 4 B | 64 B | **800 B**（200 × float） |
| 答辩风险 | 「你的 AI 在哪」 | **「AI 学到的是不是就是均值」** | 无，和参考案例同构 |
| 实测检出率 | 100%（阈值 12.0） | 未知（预计同 A） | 未验证（需采数据） |

**我的建议**：
- **时间够 → 走 C**。这是唯一既满足老师「单一变量」、又真正用上 AI、还能对标已有成功案例的路。而且能把 `fastcap` 从「并行取证的死数据」变成主线，论文里是一段很好的演进叙事。
- **时间紧 → 走 A**，论文里这样写：「实验证明在负载类异常上，单变量 RPM/V 阈值即可达到 0% 误报 / 100% 检出，多维模型相对单变量没有带来增益 —— 这本身就是有价值的负面结论，说明传感器选型正确时无需依赖高维特征。」
- **不建议走 B**：形式上像 AI，实质是阈值，答辩被问穿会很被动。

### 8.6 另一处差异：相似度阈值不能照抄

| | 别人的例子 | 本项目 |
|---|---|---|
| 相似度阈值 | `SIMILARITY_NORMAL_MIN = 90` | `AI_MONITOR_THRESHOLD = 48` |
| 学习窗口数 | `LEARNING_ITERATIONS = 50` | `AI_MONITOR_LEARN_WINDOWS = 22` |

两套库（不同 ID、不同训练结果）的相似度标度**不可通用**。改方案后阈值必须重新标定，不能直接把 90 填进来。
