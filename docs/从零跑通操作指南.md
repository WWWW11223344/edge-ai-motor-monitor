# 从零跑通操作指南

> 面向对象：拿到这台样机（或拿到本压缩包里的源码）之后，需要**自己把它装起来、烧进去、开起来、看懂屏和网页**的人。
> 写法原则：每一步都给出「在哪里做、做什么、做完应该看到什么」。不写原理推导，原理在《设计方案》和《答辩问答》里。
> 版本：2026-10-22。对应固件：STM32 UI v1.6 / D1 `d1-telemetry-2.1.11`。

---

## 0 五分钟速查（已经装好、只想开机看效果的人走这里）

1. 电池接 D153C 的 `VIN+ / GND`，红接正、黑接负。
2. 板上 USB 插电脑（只是供电，不接也行），OLED 亮，显示 `Spd 0 rpm`、底条 `DET OFF`。
3. 按一下 **K1**（升档）→ 底条变 `L1`，电机开始转，底条阶段字变 `LRN`，第 6 页中间出现 `32/64` 往上数。
4. 约 **6~10 秒**数满，阶段字变 `DET`，相似度显示 `S:100`，此时进入在线检测。
5. 用手捏住电机轴 3~3.5 秒：`R` 掉、`dR` 冲过 1.0、底条状态变 `ALARM`，板载红灯（PF9）亮；松手 0.4 秒内自行解除。
6. 手机连上 D1 的热点 `Motor-XXXXXX`（密码 `motor12345`），浏览器打开 `http://192.168.4.1`，看到同一份数据的网页版。

以上任何一步对不上，跳到第 11 章「故障排查」。

## 2 接线（逐根对照，接完打勾）

### 2.1 功率回路（粗线，红黑分开走）

| 从 | 到 | 线色建议 | 备注 |
|----|----|---------|------|
| 电池 `+` | D153C `VIN+` | 红 | 这是唯一的功率电源入口 |
| 电池 `-` | D153C `GND` | 黑 | |
| D153C `M1 OUT+` | ACS712 `IP+` | 红 | 电流串在驱动输出与电机之间 |
| ACS712 `IP-` | 电机 `M+` | 红 | |
| 电机 `M-` | D153C `M1 OUT-` | 黑 | |

> 顺序不能颠倒：**驱动 → 电流传感器 → 电机**。把 ACS712 接到电池一侧就变成测母线电流，读数含义完全不同，文档里所有 dR 数值都对不上。

### 2.2 控制信号（细线，杜邦）

| 从（MCU 引脚） | 到（模块引脚） | 作用 | 漏接的后果 |
|---------------|---------------|------|-----------|
| `PE5`（TIM9_CH1） | D153C `H1-1 BIN1` | 正转 PWM | 电机不转 |
| `PE6`（TIM9_CH2） | D153C `H1-2 BIN2` | 反转 / 刹车 | 只能单向 |
| `PA8` | D153C `H1-3 STBY` | 驱动使能，**必须高** | 电机一格都不转，且看不到任何报错 |
| 编码器 `A` | 板载 `H2`（→ `PB6` TIM4_CH1） | 测速 | 转速恒 0，屏上 `WARN` |
| 编码器 `B` | 板载 `H2`（→ `PB7` TIM4_CH2） | 测向 + 四倍频 | 转速只有一半 |
| 编码器 `VCC` | `5V` | 编码器供电 | 无脉冲 |
| 编码器 `GND` | `GND` | | |
| ACS712 `OUT` | `PA5`（ADC1_IN5） | 电流采样 | 电流恒读 0.00 |
| 板载 `H2-5` | `PA4`（ADC1_IN4） | 母线电压（板载 10k+1k 分压 1/11） | 母线显示 `--`，R 算不出 |
| `PB10`（USART3_TX） | D1 mini `D6`（= GPIO12，RX） | 遥测单向发送 | 网页一直是「等待数据」 |
| `5V` | D1 mini `5V` | D1 供电 | D1 不亮 |
| `GND` | D1 mini `GND` | **必须共地** | 网页能开但数据全是 `--` |

### 2.3 板载已接好的（不用插线，只需确认）

- OLED：`PB8 = SCL`、`PB9 = SDA`，板载 I2C。
- 三个按键：`PE4 = K0 急停`、`PE3 = K1 升档`、`PE2 = K2 降档`，1 ms 中断消抖。
- 报警指示灯：`PF9`，**低电平点亮**（阳极接 3V3，阴极由 PF9 拉低）。
- 调试串口：板载 CH340C，`PA9 = TX`、`PA10 = RX`，出 PC 的 COM 口。

### 2.4 上电前检查（四条，一条不省）

1. **不接电池**，用万用表量 `VIN+` 与 `GND` 之间电阻，不能是 0（短路）也不能是无穷大（虚接）。
2. 用万用表通断档确认 `PA8` 到 D153C `STBY` 是通的。这一根线没接好，现象和「固件坏了」一模一样。
3. 编码器 6P 排线插到底，`H2` 有防呆，插反插不进，别硬怼。
4. 所有 GND 最终汇到一个点（单点共地），不要把电机地直接当信号地。

## 3 打开工程并编译（STM32）

1. 打开 `01_STM32固件_Keil工程/USER/STM32F407_Template.uvprojx`。
2. `Project → Rebuild all target files`（全量重建，不要只 Build，避免用到旧 `.o`）。
3. 底部 Build Output 必须看到这两行：

```
Program Size: Code=22644 RO-data=6544 RW-data=276 ZI-data=17988
"..\OBJ\STM32F407_Template.axf" - 0 Error(s), 0 Warning(s).
```

四个数字对不上就说明源码被改过；`0 Error(s), 0 Warning(s)` 是硬要求，**警告也要清零**。

4. 编译产物在 `OBJ/`：
   - `STM32F407_Template.axf`（带调试信息）
   - `STM32F407_Template.hex`（烧录用）

命令行编译（不想开 GUI 时）：

```bat
UV4.exe -b USER\STM32F407_Template.uvprojx -j0 -o H:\build\log\build.log
```

> `-o` 后面必须给**绝对路径**，给相对路径不会生成日志文件，看起来像「没反应」。

## 4 烧录 STM32（J-Link）

### 4.1 用打包里的脚本（推荐）

`01_STM32固件_Keil工程/OBJ_firmware/burn_final_20261022.jlink` 内容如下，**第一行 `device STM32F407ZG` 绝对不能删**：

```
device STM32F407ZG
speed 4000
h
r
h
w4 0x40026440 0x00000000
w4 0x40012108 0x00000000
w4 0x40012304 0x00000000
erase
loadfile H:\STM32_LERN\19_OLED\OBJ\STM32F407_Template.hex 0x08000000
r
exit
```

执行：

```bat
E:\Keil_v5\ARM\Segger\JLink.exe -CommanderScript burn_final_20261022.jlink
```

其中三行 `w4` 是**烧前先关掉三个会抢总线的外设**：ADC2、DMA2、以及 ADC 公共寄存器。不关的话 erase/loadfile 会偶发失败。

### 4.2 三个坑（每一个都真实踩过）

| 现象 | 真正原因 | 处理 |
|------|---------|------|
| 日志里 `erase` 报错但 `loadfile` 照样打印 `O.K.` | 脚本没写 `device STM32F407ZG`，J-Link 拿默认芯片型号去擦，擦错了地址 | 补上第一行，重新跑 |
| 连着报 `Cannot connect to target` | 上一轮 J-Link 会话没断干净（进程还挂着） | 拔插 USB，或换 `burn_icm_retry.jlink`（在 `h` 后面多一次 `r`、速度降到 4000 再试） |
| 烧完没反应，读回 flash 一字未变 | 上面那种「静默失败」 | 烧完必须回读校验，见 4.3 |

### 4.3 烧完必须回读校验

不要只信日志里的 `O.K.`。用打包里的 `_verify_flash_full.py`，或者 J-Link Commander 里：

```
device STM32F407ZG
speed 4000
h
mem32 0x08000000 8
```

判定标准：**烧进 flash 的整片映像应为 29464 字节，且逐字节一致**。这个数 = Code 22644 + RO 6544 + RW 276，也就是 `.hex` 展开后落在 0x08000000 起的长度。上一版是 29508 字节，v1.6 删掉底条心跳后正好少 44 字节 —— 数字对不上就说明源码或烧录有一边出了问题。

## 5 烧录 D1 mini 并配网

### 5.1 编译（arduino-cli）

```bat
arduino-cli compile --fqbn esp8266:esp8266:d1_mini --output-dir out d1mini_telemetry.ino
```

- core 版本必须是 **3.1.2**，别的版本 API 有差异。
- 编译完看两行占用：Flash 约 29%，**IRAM 约 94%**。IRAM 已经很满，加功能前先想清楚放不放在 RAM 里。
- 一次编译约 24 秒。

用 Arduino IDE 的话：开发板选 `LOLIN(WEMOS) D1 R2 & mini`，`Sketch → Export compiled Binary`，产物同样在 sketch 目录下的 `out`/`build` 里。

### 5.2 烧录 + 逐字节校验

```bat
python -m esptool --chip esp8266 --port COM5 --baud 460800 ^
  write_flash --flash_mode dio --flash_freq 40m --flash_size 4MB ^
  0x0 out\d1mini_telemetry.ino.bin

python -m esptool --chip esp8266 --port COM5 --baud 460800 ^
  verify_flash 0x0 out\d1mini_telemetry.ino.bin
```

必须看到 `verify_flash` 打印 **digest matched**。只写不验，和 4.2 的坑是同一类问题。

> 端口认准 **D1 的 USB 口**（本项目是 COM5），板载调试口是另一个 COM（本项目 COM7），两者别搞混。

### 5.3 配网（两种模式，自动选）

**模式一：接现场 WiFi / 手机热点（推荐，手机和电脑都能看）**

编辑 `02_D1mini网页监视器/wifi_config.h`：

```c
#define D1_WIFI_SSID     "你的WiFi名称"
#define D1_WIFI_PASSWORD "你的WiFi密码"
#define D1_WIFI_CONNECT_TIMEOUT_MS 20000UL
```

重新编译烧录。上电后 D1 先当 STA 连这个 WiFi，连上后从路由器拿 IP。

**查当前 IP**：USB 串口连 D1，敲一个小写字母 `p` 回车，会打印 `STA_IP=...`、`STA_GW=...`。本项目实测过的是 `192.168.157.79`，**这个地址是 DHCP 分的，会变，用前一定重新查**。

**模式二：连不上就自己开热点（兜底，永远可用）**

- 热点名：`Motor-XXXXXX`（`XXXXXX` 是芯片 ID，多块板子能区分）
- 密码：`motor12345`（固定值，输一次就能一直用）
- 手机连上后浏览器打开 **`http://192.168.4.1`**

### 5.4 一个必须知道的细节

**插拔 D1 的 USB 会让它复位**（CH340 的 DTR/RTS 接了 RST/GPIO0）。所以：

- 用脚本读串口之前，先 `ser.dtr = False; ser.rts = False`，再 `open()`；
- 上电后 **20 秒内**不要发 `?` 查询，否则会打断它配网，看到假的 `ready:false`。

## 6 第一次上电（按这个顺序，别跳步）

1. **什么都不按**，接电池。OLED 亮，显示：
   - `Spd 0 rpm`、`Cur 0.00 A`、`R --.-- rpm/V`、`Bat 10.x V`
   - 底条：`DET OFF` —— `OFF` 就是 0 档，此时 PWM 占空比 0，电机断电。
2. 按 **K1** 一下：底条 `OFF` → `L1`（占空比 58%），电机开始转。
3. 底条阶段字从 `DET` 变 **`LRN`**，第 6 页中间出现 `32/64` 这样的进度，约 6.4 秒数到 `64/64`。
4. 数满后阶段字回 **`DET`**，中间格显示 `S:100`（相似度），底条状态 `RUN`。**这一刻起才真正在检测**。
5. 再按 **K1**：`L1` → `L2`（64%），转速上到约 245 rpm。**切档会清窗重学**，屏上重新走一遍 `LRN`，约 10 秒恢复（3.2 s 攒满 32 点窗 + 6.4 s 学 64 窗）。
6. 按 **K2** 降档，按到 0 档即 `OFF`。按 **K0** 是急停，任何档位一键归零。

## 7 看懂 OLED（逐行对照）

屏是 128×64，分 8 页，用两种字号：大字号 8×16（占 2 页），小字号 6×8（占 1 页）。实际版面：

```
Spd      141     rpm     <- 页 0~1，大字号：转速
Cur     0.10       A     <- 页 2~3，大字号：电枢电流
R      13.04    rpm/V    <- 页 4~5，大字号：归一化转速比 R，只做屏显
Bat  10.8V  S:100  RUN   <- 页 6，小字号：母线电压 / 相似度或学习进度 / 状态字
DET L1   dR 0.39  01396 s<- 页 7，小字号：阶段 / 档位 / dR / 运行秒数
```

逐字段说明：

| 字段 | 含义 | 有效范围 | 读到什么说明有问题 |
|------|------|---------|------------------|
| `Spd` | 转速，编码器四倍频 1040 counts/圈 换算 | 0~500 rpm | `WARN` 且转速为 0 → 编码器没接或没转 |
| `Cur` | 电枢电流，ACS712 测、零点上电校准 | 0.00~1.50 A | 恒 `--.--` → ADC1_IN5 没信号 |
| `R` | `(转速 / 母线电压) × (58-50)/(占空比-50)`，归一化转速比 | 空载约 13，重载下降 | `--.--` → 未在转、或电压通路坏、或占空比 ≤ 50% |
| `Bat` | 母线电压，板载 1/11 分压 | 4.0~16.0 V 有效 | `--` → PA4 没接 |
| `S:100` | 相似度 0~100，**≥ 32 判正常** | 正常侧最低实测 44 | 停机时显示 `S:  0` |
| `32/64` | 现场学习进度（学习阶段才出现，占同一格） | 数到 64/64 | 长时间停在中途 → 电机转速不稳或低于 20 rpm |
| `RUN/STOP/WARN/ALARM` | 界面状态字，5 字定宽 | 四选一 | `WARN` 一出现先查接线，不是 AI 报警 |
| `DET` / `LRN` | 阶段标记：检测中 / 学习中 | 二选一 | 一直 `LRN` → 学不满，见上 |
| `L1`/`L2`/`OFF`/`MIN` | 档位号，**不显示占空比** | 1 / 2 / 停转 / 扫描哨兵 | — |
| `dR` | 3.2 s 窗内 rpm/V 的绝对峰峰值，**报警门限 1.0** | 稳态 0.2~0.6，捏放 2.0~3.x | `----` → 窗口未满 |
| `01396 s` | 上电运行秒数，5 位补零 | 0~99999 | 秒数后**不再有任何字符**（心跳指示已删除） |

四个状态的对照图见 `06_图示/屏面版式_正常检测.png`、`屏面版式_学习中.png`、`屏面版式_停机.png`。
真机实拍（L2 档 237 rpm、dR 0.21）见 `06_图示/实物照_OLED运行显示.jpg`，可以拿它和渲染图逐字对照——
两者字位应当完全一致，对不上就说明代码或字库不是这一版。

**状态字优先级**（先命中先显示，每轮只取一个）：

1. 过流保护动作，或任一观测量无效 → `WARN`
2. 转速 < 20 rpm → `STOP`
3. AI 判据或 dR 判据成立 → `ALARM`
4. 其余 → `RUN`

## 8 看懂手机网页

页面由 D1 自己承载，STM32 只发 42 字节/100 ms 的帧、完全不参与渲染。所以**断网不影响 OLED，断电 D1 也不影响 OLED**，两条通道互相独立。

从上到下五个区块：

| 区块 | 内容 | 怎么看 |
|------|------|-------|
| 顶部胶囊 | `通信正常` / `等待数据` / `通信中断` | 红色胶囊 = D1 收不到 STM32 的帧，先查 `PB10 → D6` 和共地 |
| 判定主卡 | 大标题六态：正常 / 学习中 / 异常 / 待机 / 未启用 / 推理故障 | 卡内两个核心量：转速、特征比值 R；下方是 `dR` 与门限 1.0 的进度条，满格=已越门限 |
| 近 60 秒趋势 | 转速（蓝）与 R（紫）双曲线，Canvas 现画 | 两条线各自按自己窗口的极值缩放，所以小波动看起来不会被放大 |
| 数据清单 | 电流、母线电压、档位 | 档位显示 `L1/L2/OFF/MIN`，**不显示占空比**（58/64 是标定参数，不是操作量） |
| 底部诊断 | 已运行秒数、数据年龄、有效帧/异常帧、固件版本 | 「数据年龄」持续 > 2 s 说明链路卡住 |

四态参考图：`06_图示/页面实拍_正常检测.png`、`页面实拍_异常报警.png`、`页面实拍_学习中.png`、`页面实拍_停机.png`。

> 页面只做 GET `/status`，**没有任何会改数据的按钮**。想改档位只能用板上三个按键。

## 9 三个按键

| 按键 | 引脚 | 作用 | 备注 |
|------|------|------|------|
| K0 | `PE4` | 急停，立刻回 0 档、PWM 清零 | 出任何异常先按它 |
| K1 | `PE3` | 档位 +1（0 → L1 → L2） | 到 L2 后再按无效 |
| K2 | `PE2` | 档位 -1 | 到 OFF 后再按无效 |

两条行为要记住：

- **任何按键都会清过流保护的锁存**。过流保护动作后 PWM 被清零、屏上 `WARN`，按任意键解锁才能重新给占空比。
- **升档 / 降档都会清窗重学**。上一档学到的基线对本档无效（两档 R 差 6.3%，超出模型 ±1% 的带宽），所以切档后必然重走一遍 `LRN`，约 10 秒恢复检测。

## 10 做一次报警实验（答辩现场可复现）

1. L1 档转起来，等到底条 `DET` + `S:100`，且 `dR` 稳定在 0.2 左右。
2. 用手（或软布包住的钳子）捏住电机轴，**持续 3~3.5 秒**。
3. 观察三件事同时发生：
   - 转速掉到约 85 rpm（−40%），`R` 从 13 掉到 8 附近；
   - `dR` 冲到 2.0~3.0，越过门限 1.0；
   - 底条状态变 `ALARM`，板上红灯（PF9）亮。网页同时变红。
4. 松手，**0.4 秒内自行解除**，无需复位。
5. 想验证「不误报」：只轻碰一下马上松手，`dR` 单窗超限但连击不足 2 窗，不会报。

> 报警判据是**并联的两条**：AI 相似度连续 2 窗 < 32，**或** `dR ≥ 1.0` 连续 2 窗。任一条成立即报警。

## 11 故障排查（按现象查）

| 现象 | 最可能的原因 | 处理 |
|------|-------------|------|
| 上电后 OLED 全黑 | ① 板子没供电；② 烧录静默失败；③ 固件卡在 IWDG 之前 | 先量 3V3；再按 4.3 回读 flash；最后重新烧 |
| OLED 亮但 `Spd` 恒 0，按 K1 电机也不转 | `PA8`（STBY）没接或没拉高 | 万用表量 PA8 是否 3.3 V；驱动板 STBY 必须为高 |
| 电机转但 `Spd` 恒 0 | 编码器 A/B 没接、或只接了一相 | 量 PB6/PB7 是否有脉冲；`H2` 排线插到底 |
| `Bat` 显示 `--` | `PA4` 没接（`H2-5`） | 补线；量分压点对地电压应为母线 1/11 |
| `Cur` 显示 `--.--` | `PA5` 没接 | 补线；ACS712 输出静态应为 2.5 V 左右 |
| `dR` 一直 `----` | 窗没满（< 32 点），或转速 < 20 rpm 一直在丢窗 | 让电机稳定转 4 秒以上 |
| 一直停在 `LRN`，进度不动 | 转速低于 20 rpm，`feature_r_tick()` 直接丢弃 | 升到 L1；检查是否带载太重 |
| 网页「通信中断」 | ① `PB10 → D6` 没接；② 没共地；③ D1 掉线 | 依次查线、查共地；USB 串口敲 `p` 看链路 |
| 网页能开但数据全 `--` | 帧收到了但字段无效（缺路） | 页面会逐路点名「未采到：电流 / 母线电压」 |
| 手机打不开网页 | 书签还停在旧 IP | 串口敲 `p` 查当前 IP；或让 D1 开热点用 `192.168.4.1` |
| 连热点后浏览器报 502 | 电脑/手机开了系统代理，把内网地址也代理走了 | 关代理，或把 `192.168.*` 加入例外 |
| 驱动板发烫、几秒后电机停 | 过流保护动作（正常行为） | 查机械是否卡死；**不要**为了「跑起来」去改 `GUARD_*` 门槛 |
| 电机完全不转、`WARN` 常亮，按键也没用 | 保护已锁存 | 按任意键解锁；仍不行查 I²t 是否又立刻耗尽 |

## 12 采集数据集与重训模型

### 12.1 采集（走 D1 的 USB，不走 WiFi）

1. USB 连 D1，串口波特率 115200。
2. 发一个小写 `u`：D1 回 `USB_BEGIN{...}`，随后按 42 字节/帧连续吐数据，最后 `USB_END`。
3. 发 `s` 可以随时中止；发 `?` 只做一次握手（回 `USB_READY{...}`）。
4. 用 `output/jump_feature_20261021/capture_d1.py` 采集，输出 `Ripple32_*.csv`。

> 采数据的铁律：**必须走 USB**。WiFi 能连上但笔记本常常跨网段（例如 D1 在 192.168.157.x、笔记本在 192.168.0.x），抓包会丢帧，白费功夫。

数据集格式（现行）：

| 文件 | 行数 | 用途 |
|------|------|------|
| `Ripple32_regular_normal.csv` | 2252 | 正常样本，训练 + 正常侧误报统计 |
| `Ripple32_abnormal_grip.csv` | 3378 | 捏放异常样本，训练 + 检出率统计 |
| `Ripple32_test_normal.csv` | 1126 | 独立正常样本，只做验证不参与训练 |

三个文件都是每行 32 个数，无表头、无标签。

每行 = 连续 32 个「8 点峰峰值 PtP」，不是 32 个 R，也不是 32 个 dR。

### 12.2 重训（NanoEdge Studio）

完整步骤见 `docs/NanoEdge训练操作手册_20261019.md`。关键参数：

- 信号长度 32，维度 1
- 预处理：`absolute → extract_features(n95, peak_value, n25) → interleaved`
- `input_size = 3`，聚类数 35，sensitivity 0.5，`learning_min_lines = 368`
- 期望占用：RAM 3668 B / Flash 3108 B

换库之后要同步改这几处：

| 位置 | 宏 | 现值 |
|------|----|------|
| `ai_monitor.h` | `AI_MONITOR_THRESHOLD` | 32 |
| `ai_monitor.h` | `AI_MONITOR_LEARN_MAX` | 400 |
| `ai_monitor.h` | `AI_MONITOR_SITE_LEARN_WINDOWS` | 64 |
| `feature_r.h` | `RIPPLE_ABS_ALARM` | 1.0 |
| `feature_r.h` | `RIPPLE_ALARM_WINDOWS` | 2 |
| `NEAI/` | `libneai.a` | 直接替换整个目录 |

改完重新编译，**尺寸必须重新记录**（当前基线：Code=22644 / RO=6544 / RW=276 / ZI=17988，全片 29464 字节）。
