# 数据集说明（2026-10-21 定版）

## 1 这三个文件是什么

| 文件 | 行数 | 用途 |
|---|---|---|
| `Ripple32_regular_normal.csv` | 2252 | 正常工况，NanoEdge 的 nominal 集，用于建基线 |
| `Ripple32_abnormal_grip.csv` | 3378 | 捏住输出轴，NanoEdge 的 anomaly 集，只参与评估 |
| `Ripple32_test_normal.csv` | 1126 | 独立第 6 批正常数据，不参与训练，只做泛化复核 |

## 2 格式

- **一行 = 一个样本，正好 32 个数**，空格分隔，无表头、无标签、无行号；
- 编码 UTF-8（纯 ASCII 数字），行尾 LF，文件末尾有换行；
- 全部是非负浮点数，量纲为 **rpm/V**。

## 3 每一行的物理含义

固件每 100 ms 推一个点，先得到原始比值

```
q[i] = rpm[i] / vbat[i]         单位 rpm/V，不做膝点归一化
```

再在最近 8 个点上取极差（滚动峰峰值，跨度 0.8 s）：

```
r[i] = max(q[i-7 .. i]) - min(q[i-7 .. i])
```

一行 32 个 `r` 覆盖 **32 × 100 ms = 3.2 s**。

### 为什么是峰峰值而不是 R 的电平

NanoEdge 的库会对输入做池化／特征提取。**电平（均值）在池化后会被平均掉**，
所以"平均 R 掉了一点"这种异常在库里几乎看不见；而峰峰值是取极差，
一次瞬时跌落就直接顶上去，不会被抹平。同批数据的实测对比：

| 判据 | 检出率 | 口径 |
|---|---|---|
| R 电平 + 均值池化 | 58.9% | 模拟库内池化 |
| **滚动峰峰值（本数据集）** | **87.0%** | 离线预估 |
| 滚动峰峰值 → ICM 库 | **92.0%** | 混淆矩阵实测 |
| 对照：dR 固定阈值 1.0（不经模型） | 87.6% | 每行取 32 个 PtP 的 max |

### 为什么不对 r 做膝点归一化

峰峰值与转速**不成正比**：58% 档约 0.103、64% 档约 0.120。
如果照搬 R 的膝点归一化（乘 8/(duty-50)），64% 档会被缩小 0.571 倍，
两档数据反而对不齐。所以本数据集保持原始 rpm/V 量纲。

好在峰峰值对档位几乎不敏感：捏轴时两档分别是 0.834 与 0.836（差 0.2%），
这正是"一份预训练知识两档通用"的依据。

## 4 采集条件

- 电机：WHEELTEC MG310（13 PPR × 4 倍频 × 20 减速比 = 1040 counts/圈）；
- 档位：58% 与 64% 两档都用，混合成一份数据集；
- 母线：3S 锂电，10.8 ~ 11.9 V（记不清具体值没关系，比值里已经除掉电压）；
- 异常的定义：手指捏住输出轴，转速明显下降但不堵死。

## 5 与旧数据集的区别

`R32_*.csv`（2026-10-19 版，已删除，可在 git 历史里查到）存的是**单点 R 的值**，
一行 32 个连续时刻的 `rpm/V`。那一版的库是 ZSM，内部把 32 点均值池化成 1 个值，
等价于一行阈值 `if`，所以检出率只有 58.9%。本版换成峰峰值后重训为 ICM 库。

改动原因与完整对比见 `docs/训练与选型记录_20261021.md`。
